# LBS P0–P2 浏览器人工验收清单

> 使用真实高德环境时由 Next.js 自行加载 `.env.local`。不要在命令、截图、DevTools 导出或验收记录中复制、打印或保存任何 Key。

## 清单 1：保存链路

1. 在 PowerShell 7 中运行 `npm.cmd run dev`。
2. 打开 `http://localhost:3000/portfolio/new`。
3. 填写“房源标题 *”“月租金 *”“面积 *”“户型 *”“所在区域 *”等必填项。
4. 在“位置提示 *”输入“望京”，等待候选下拉：
   - 真实高德环境：用键盘 `↓` 选择实际返回的望京相关 POI（例如“望京 SOHO”，候选文字以实时结果为准），按 Enter；
   - mock 环境：候选主文本是“望京”，副文本是“模拟位置候选”，不应硬编码期待真实 POI。
5. 点击“保存到候选房源”。
6. 断言 URL 跳转到 `/portfolio/{id}`。
7. 打开 DevTools → Application → Local Storage，检查 `housefolio:listings`。
8. 找到刚保存的新记录并断言：
   - `addressHint` 只包含选中后的名称/区域展示值；
   - `district` 是独立的区域字符串；
   - 不存在 `lat`、`lng`、`latitude`、`longitude`、`coordinate`、候选详细地址或完整候选对象。

## 清单 2：锚点上限

1. 打开 Settings → “工作/学习地点（通勤锚点）”，添加 4 个不同地点。
2. 打开任一具有位置提示的房源详情 → 通勤面板。
3. 确认 4 个已存锚点全部可见，且默认只勾选前 3 个。
4. 断言第 4 个未选 checkbox 为 disabled，不能在已选满 3 个时继续勾选。
5. 取消任一已选锚点，断言第 4 个 checkbox 恢复可选，并可将总数重新选到 3 个。
6. 回到 Settings 或检查 `housefolio:work-locations`，断言原有 4 个锚点均未被删除。
7. 仅准备 3 个或更少锚点时，断言所有 checkbox 均可选。

## 清单 3：四方式计算与持久化

1. 打开房源详情 → 通勤面板，仅保留一个锚点以便核对结果。
2. 依次选择“公共交通”“步行”“骑行”“驾车”：
   - 每次断言四个 radio 互斥；
   - 每次点击对应的“计算…参考通勤”按钮；
   - 每次断言结果卡“方式”标签与所选方式一致。
3. 刷新详情页。
4. 断言 `housefolio:commute-results` 中存在每个已成功计算的 `(listingId, anchorId, mode)` 记录，`mode` 分别为 `transit`、`walking`、`cycling`、`driving`。
5. 断言数组中的最新记录对应最后一次成功计算的 mode；同一房源、锚点和 mode 重算只替换该条，不删除其他 mode。
6. 断言刷新后四种已保存结果仍显示。
7. 注意：刷新后 radio 会恢复默认“公共交通”，最后选中的 radio 本身不持久化；持久化的是计算结果。
8. 断言 L2 顶部评分仍只使用公共交通结果，没有改成其他方式。
